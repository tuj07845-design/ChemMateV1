ChemMate V1 工程化验收标准

一、验收目标

对 ChemMate V1 进行工程化验收。

V1 的核心目标是验证以下完整闭环：

> 用户任务 → Agent → Tool → Aspen Plus → 数据结构化 → MATLAB → Agent分析 → Word报告



该闭环是 V1 的核心功能，不要求 V1 达到工业级生产系统标准，但必须达到可运行、可验证、可维护、可扩展的工程化 Demo 标准。
项目当前技术路线中明确要求 Agent 作为总控、Tool 作为执行能力、模块通过结构化数据连接，并要求 V1 优先完成真实闭环、避免过度设计。

评分

0分：无法形成闭环

2. 数据正确性：20分

重点验证 data_get。

至少检查：

Stream

Block

Connection

Temperature

Pressure

Vapor Fraction

Mass Flow

Mole Flow

Mole Fraction

Mass Fraction

Component Data

Unit


这些属于当前 V1 技术路线中明确的数据范围。

评分

20分：核心数据与 Aspen 一致，结构完整

15分：少量非核心字段存在问题

10分：核心数据基本正确，但存在明显缺失

5分：只能读取部分数据

0分：数据无法验证或明显错误


禁止“程序运行成功=数据正确”的判定方式。


---

3. Tool工程化：15分

检查：

Tool职责是否单一

输入是否明确

输出是否结构化

成功/失败状态是否明确

Tool是否可以独立测试

Tool之间是否存在不合理耦合


当前架构要求 Tool 独立，并通过结构化数据连接。

评分

15：接口清晰、独立性良好

12：基本工程化，有少量耦合

8：能够工作，但接口混乱

4：大量硬编码/互相依赖

0：无法独立维护



---

4. Agent总控：10分

验证 Agent 是否真正承担：

理解任务

判断需要哪些 Tool

决定调用顺序

传递 Tool 输出

判断执行结果

处理异常

分析结果


而不是由 main.py 把完整流程全部写死。

这是当前 V1 架构对 Agent 的核心定义。

评分

10：Agent真正负责流程控制

7：Agent参与主要决策，但部分流程硬编码

4：Agent主要只是调用入口

0：Agent不承担总控职责



---

5. 异常处理：15分

至少测试：

1. Aspen文件不存在


2. Aspen启动/加载失败


3. Aspen运行失败


4. data_get失败


5. MATLAB调用失败


6. Tool返回异常数据



合格标准

系统必须：

> 识别错误 → 明确返回错误 → 阻止错误结果继续传播



不能出现：

> Tool失败 → Agent不知道 → 继续生成“正常报告”。



评分

15：主要异常均可识别、定位、处理

10：能够识别异常，但恢复能力有限

5：部分异常能够捕获

0：异常直接导致系统崩溃或产生伪成功结果



---

Agent与Tool分离

Tool之间低耦合

配置与代码分离

函数职责清晰

评分

10：结构清晰，可继续开发

7：基本模块化

4：存在明显结构问题

0：基本属于脚本堆叠

1：必须修改代码

0：只能运行当前固定案例

---

四、一票否决项

即使总分达到80分，只要以下任一项为0分，不得宣布 V1 完成：

1. 完整功能闭环


2. 数据正确性


3. Tool工程化


4. 异常处理



尤其是：

> 不能因为“成功生成了一份 Word”就判定 V1 合格。



必须证明数据来源正确、流程真实运行、模块之间接口正常。
