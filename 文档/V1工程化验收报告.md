## 九、性能观察与后续优化（2026-09-04 任务三补充）

### 背景：UI 真实任务耗时 9+ 分钟（19:10:42 → 19:22:49 仍在运行）

日志时间线分解（用户 UI 运行实录）：

| 时段 | 阶段 | 耗时 | 评价 |
|---|---|---|---|
| 19:10:42→19:11:17 | 第 1 轮 + data_get_process（Aspen 启动+取数） | ~35s | 正常（Aspen COM 启动固有开销） |
| 19:11:17→19:21:29 | **第 2 轮模型回复**（思考→决定调用 analyze） | **~10min** | 异常热点：模型侧深度思考 + 上下文过大 |
| 19:21:29 | analyze_process 执行 | 秒级 | Observation summary 正常 |
| 19:21:29→19:22:38 | 第 3 轮模型回复（含截断多余 Thought） | ~1min | 上下文变小后明显加快 |
| 19:22:38→19:22:49 | draw_mat（MATLAB 出图） | ~11s | 正常 |

### 结论：功能稳定优先，速度列入后续优化

- **模型链路本身很快**：实测小请求 2.2s 返回（2026-09-04 19:46，max_tokens=20）。
- **模型曾换 3 个测试**：默认 qwen3.8-max → 测试期更换，当前 .env 为 glm-5.2（经 dashscope 兼容端点）。深度思考型模型在复杂决策轮耗时可达数分钟，属模型特性而非代码缺陷。
- **次要放大因素**：data_get 的 Observation 全量 JSON 达数百 KB（本次实测输出 1795+ 行），第 2 轮 prompt 携带巨量上下文，放大了模型处理与网络耗时。
- **判定**：链路稳定可复现（本次任务最终成功产出图与报告），按「稳定优先于速度」原则不阻塞验收；速度列为 V1 后续优化项。

### 后续优化清单（不阻塞验收）

1. 模型策略：提供可切换配置（快模型/思考模型分轮使用），默认换回低延迟模型；
2. Observation 摘要化：data_get 返回默认只带 summary + 落盘文件引用，完整 JSON 按需读取（防上下文膨胀）；
3. prompt 上下文裁剪：历史轮次截断/摘要，控制单轮请求体积；
4. LLM 调用流式化 + 前端打字机效果（感知提速）；
5. max_rounds 细化 + 每轮超时上限提示。
